## What exists

- Runtime: `linux-port/overlays/playerbot/src/game/src/playerbot_i18n.h` (MT2009_PLUS_BOT_I18N_V1).
  The bots keep writing Polish. The finished Polish line is matched against the catalog
  `chat_<lang>.tsv` and the reader gets the translation. Slot values are translated again
  (place phrases, monster families) or by vnum (item and monster names, `names/`).
- Data (shipped to `/opt/metin2/share/locale/poland/playerbot_i18n/` by the game Dockerfile):
  `linux-port/docker/game/playerbot_i18n/`
  - `catalog_pl.tsv` – every Polish template (4075 keys). Generated, never edited by hand.
  - `chat_<lang>.tsv` – `Polish<TAB>translation`. A language exists when this file exists.
  - `input_<lang>.tsv` – the player's words -> the bots' Polish (understanding). `input_en.tsv`
    is hand-written; the others are generated by `tools/playerbot_i18n/gen_input.py`.
  - `names/item_names_<lang>.txt`, `names/mob_names_<lang>.txt` – `vnum<TAB>name` (Owsap dumps).
  - `config.tsv` – switches. `/opt/m2spool/playerbot_i18n.tsv` overrides them.
- Tools: `tools/playerbot_i18n/` – `extract_pl.py`, `staging.py`, `check_catalog.py`,
  `gen_input.py`, `gen_names.py`, `gen_codepages.py`, `manual_pl.tsv`, `TRANSLATOR_RULES.md`.

## Remaining work, step by step

The staging files are ready in `/opt/metin2/cache/i18n-staging/bots/<lang>/<lang>_NNN.tsv`
(`pt_001..010`, `gr_001..010`, `hu_001..014`, about 300 rows each). The translator rules are
`/opt/metin2/cache/i18n-staging/bots/RULES.md` (a copy of `tools/playerbot_i18n/TRANSLATOR_RULES.md`).

### A. Translator (Haiku): translate only, never touch the repo

1. Read `/opt/metin2/cache/i18n-staging/bots/RULES.md` completely.
2. Open one file, e.g. `/opt/metin2/cache/i18n-staging/bots/hu/hu_001.tsv`. Each row is
   `id<TAB>Polish<TAB>English<TAB>` with the 4th column empty.
3. For every row, write the translation into column 4. Do not change columns 1-3, the row
   order or the row count. Keep every `$SLOT` and `{n}` exactly. One TAB between columns,
   no TAB inside the translation. UTF-8 with the real letters of the language.
4. Save the file under the same name. Do the next file. Never edit any other file.

### B. Integrator (Opus): validate and merge

1. `cd /opt/metin2/git/wt-y-tr-bots`
2. `python3 tools/playerbot_i18n/staging.py import pt gr hu`
   - It merges every valid filled row into `linux-port/docker/game/playerbot_i18n/chat_<lang>.tsv`
     (in catalog order), and it skips empty rows.
   - It rejects rows with a changed id or Polish column, a missing / extra / renamed slot,
     a TAB, a forbidden name (Metin2, Gameforge, official/offiziell/oficial/hivatalos/επίσημ...,
     Tieru, Ameria, metin2alerts), a letter the language's code page does not have
     (hu/cz/ro cp1250, gr cp1253, tr cp1254, the rest cp1252; Romanian ș/ț are mapped
     to ş/ţ automatically), or a length far beyond the Polish.
   - Every rejected row is listed in `/opt/metin2/cache/i18n-staging/bots/<lang>/IMPORT_REPORT.txt`
     with the reason. Fix those rows in the staging file (or send them back), then run import again.
     The import is idempotent.
3. `python3 tools/playerbot_i18n/staging.py status pt gr hu` – check the result.
4. `python3 tools/playerbot_i18n/check_catalog.py pt gr hu` – it must show
   "0 with slot or name problems" and no "not in cp" lines.
5. Optionally spot-check lines:
   `python3 tools/playerbot_i18n/check_catalog.py --line "Jestem w Dolinie Orkow." hu`
6. `python3 tools/playerbot_i18n/staging.py export pt gr hu` – rewrites the staging files with
   what is still missing (0 rows = done).
7. Commit only `linux-port/docker/game/playerbot_i18n/chat_*.tsv` (message e.g.
   "Bot i18n: Hungarian catalog"), with the session attribution lines.

## After code changes (new bot lines)

1. `python3 tools/playerbot_i18n/extract_pl.py` – regenerates `catalog_pl.tsv` from the sources
   (+ `manual_pl.tsv`, for lines the code assembles from pieces).
2. `python3 tools/playerbot_i18n/staging.py export` – every language gets the new keys.
3. Translate (A), import (B).
4. A line the catalog did not cover at runtime is written to
   `/opt/m2spool/playerbot_i18n_miss_<lang>.tsv` on the test server: add the missing pieces
   as templates to `manual_pl.tsv` (slots `$A`, `$B`...) and repeat from 1.

## Formats

- `chat_<lang>.tsv`: UTF-8. Header lines start with `#`; `#@codepage<TAB>1250` sets the
  client's code page. Rows `Polish template<TAB>translation`. Translation `-` = no text.
- Slots: `$NAME` (uppercase, conversation placeholders) and `{1}`..`{n}` (printf values in
  order). The translation must contain exactly the same set. `$MAPIN`/`$DEST`-style slots
  already contain their preposition ("in Joan", "to Joan").
- Matching is case- and accent-insensitive; a final full stop is optional; a line no single
  template covers is cut at ". ", ", ", "! ", "? " and smileys and translated piece by piece.
- `input_<lang>.tsv`: `their words<TAB>Polish words`, lowercase, `word*` = prefix;
  `#@detect<TAB>w1 w2 ...` = words that mark a line as this language (DETECT).

## Pitfalls

- Never edit `catalog_pl.tsv` by hand; never change the Polish column of a chat file – a row
  whose Polish does not match a catalog key is dead.
- A translation with a slot that the Polish lacks is printed literally ("$X"); the import rejects it.
- `/towarzysz ...` command words stay Polish (they are typed commands).
- Greek must be in Greek script (cp1253); Turkish in cp1254 – a letter outside the page is sent as `?`.
- Keep lines short: the whisper packet is cut at CHAT_MAX_LEN.
- The shipped files are read at start and re-read within a minute after a change of the
  directory (no restart needed on a running core); a Docker image rebuild is still what
  deploys them.
